# Decompose Project Apollo Declarative

Read the selected project management system and [shared conventions](../../../ai_development/project_management.md). Run when a milestone is being proposed or has just been created, using the current request and relevant retained context.

Assess the milestone's outcome, acceptance boundary, dependencies, and independently useful deliveries. Keep a coherent milestone whole when its scope already supports clear planning and progress tracking. For a goal such as creating an application or its entire design, identify meaningful smaller milestones before their implementation issues.

Propose only the grouping needed for useful delivery and visibility: issues within one milestone, or several milestones with their own outcomes. Explain each boundary and dependency in concise project terms. Use the selected system's equivalent grouping concepts.

Create or adjust the agreed items and relationships through the selected plugin within the developer's authorization. Retain the confirmed structure and rename the working chat for its finalized active milestone under the shared title conventions. Hand development-level planning to the existing `task-decomposer` skill when an issue is ready for that work.
